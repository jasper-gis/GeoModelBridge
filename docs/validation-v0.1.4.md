# V0.1.4 验证记录

日期：2026-09-21。本轮完成低内存中间包写出，并收尾已有的 JPEG 散列复用、日志限量预览和报告缺字段提示修复。按用户要求完成这一轮后结束持续优化目标。

## 优化效果

同一 Windows 机器、相同发布编译配置、同一份 8,920,976 字节真实 FBX，以 `prepare --profile gis-static --wkid 3857 --origin 0 0 0` 分别测量三次。范围是整个 CLI 准备过程，包括读取 FBX、检查和写中间包，**不包括 FileGDB 后端进程**。

| 指标 | 优化前 | 流式写出后 |
|---|---:|---:|
| 峰值工作集三次中位值 | 282,456,064 字节 | 59,609,088 字节 |
| 准备耗时三次中位值 | 0.618 秒 | 0.606 秒 |
| scene.json 大小 | 40,086,059 字节 | 40,086,059 字节 |
| scene.json SHA-256 | `555c2683a5127ad1a23ed527279fddafe641134f2b57cc124d4882c61bffc83c` | 完全相同 |

峰值内存下降约 **79%**。三次计时差异较小，本版不宣称端到端转换有明显提速。逐字节比较在统一版本号之前完成，以免版本元数据本身造成差异。原始测量见 [优化前](evidence/V0.1.4/baseline-prepare.json)、[优化后](evidence/V0.1.4/streaming-prepare.json)，[测量脚本](evidence/V0.1.4/benchmark_prepare.py) 使用 Windows 进程峰值工作集。

Reader 另行进行只含 `read_fbx` 的 ABBA 对照，30+30 次暖缓存读取，中位耗时 69.96 → 64.78 毫秒，约降低 7.4%。这项变化只复用 JPEG 修复时已经计算的 SHA-256，减少 3 次、2,368,505 字节的重复扫描；不缓存或隐藏源图片文件的变化。完整中间包的 14 个文件逐字节一致，见 [独立读取阶段证据](evidence/V0.1.4/reader-benchmark.json)。

## 交付和边界

本版保存到 `releases/V0.1.4`，入口为 `bin/geomodelbridgeGUI.exe`，应保留整个版本目录。GUI 为 Windows x64 自包含程序；CLI、原生后端与 Pro 后端版本均为 0.1.4。既有 `dist` 保留 V0.1.3，运行中的旧 GUI 不受覆盖。没有生成 ZIP，源 FBX 和既有成果不修改。

版本、程序大小和散列见 [发布文件清单](evidence/V0.1.4/release-files.json)。.NET 运行时原始许可与来源清单随发布保留。

本轮没有完成或宣称解决三维完整外观验收、历史红青双影，以及两个后端坐标量化精度的差异。原有 [V0.1.3 验证边界](validation-v0.1.3.md) 保持有效；本版低内存改善不是放宽这些检查。
