# 输入和报告边界修复验证 — 2026-10-03

本次从 `master` 的 `cf250f6` 开始，版本保持 `0.6.0`，改动列入 Unreleased。针对代码审查中实际复现的 DAE 文本截断、GUI 格式参数遗漏和 Python 报告异常上下文丢失进行修复。Scene Bundle、原生 FileGDB 编码、输出独占创建和放置契约保持不变。

## 修复与反例

- DAE 不再只读取 TinyXML-2 `GetText()` 返回的第一个文本节点。逐段读取普通文本和 CDATA，跳过注释，完整检查索引、面角点数、浮点数组、变换、轴向和图片路径。只为跨片段的单个 token 拼接暂存，普通索引列表仍直接读取，不构造完整索引数组副本。浮点文本拒绝 `+-10` 等非法双符号。
- TinyXML-2 会丢弃相邻标记之间的纯空白，因此无法判断分隔关系时明确报告 `UNSUPPORTED_DAE_XML`；数字列表中已有可见分隔符的情况仍接受。解析前校验 XML 数字字符引用，拒绝 NUL、代理项、越界和非法数字，防止解码后的 C 字符串截断后缀。注释、CDATA 和处理指令的字面文本不按字符引用解码；属性引号状态也参与检查。没有数字字符引用时跳过额外检查，索引 token 暂存跨次复用。
- GUI 用规范化输入路径判断 OBJ/MAX 格式，避免首尾空白导致 OBJ 轴向和单位、MAX 运行环境和采样参数遗漏。MAX Batch 相对路径与输入路径一起在回调前固定，工作目录变化不再改变启动或报告核验所用路径。
- Python 客户端将无效 MAX 溯源路径、过深 JSON 等报告验证异常统一转为 `ConversionError(INVALID_REPORT)`，保留报告路径、退出码、诊断、双流日志及截断标记，不删除已生成成果。MAX 协议版本必须是整数 `1`；超大 OBJ 单位值在启动前以 `ValidationError` 拒绝。完成回调异常保留已验证结果的既有行为不变。

旧 CLI 与修复版的八组 DAE 对照中，五组原本错误接受的尾部/字符引用/符号输入现被拒绝，两组合法分片文本由失败转为正确读取，处理指令中的字面引用继续接受。GUI 四项新回归在旧实现上全部失败，服务测试从 236/240 变为 240/240。旧 Python 客户端运行新增回归会出现不正确接受或裸异常；修复后通过。反例和结果保存在本次证据目录，未修改历史证据。

XML 语义依据：[W3C XML 1.0 字符范围](https://www.w3.org/TR/xml/#charsets)、[注释](https://www.w3.org/TR/xml/#sec-comments)、[CDATA](https://www.w3.org/TR/xml/#sec-cdata-sect) 和[处理指令](https://www.w3.org/TR/xml/#sec-pi)。格式支持边界见 [DAE 输入说明](dae.md)。

## 最终验证

Windows x64 使用 MSVC 14.44.35207；Ubuntu 24.04.4 LTS x86_64 使用本机 QEMU TCG 虚拟机（3 vCPU、3 GiB 内存）。两平台通过根 CMake 构建并安装完整 CLI 和官方 FileGDB API 1.5.5 原生后端；Windows 同时发布 GUI。最终改动源码在两平台逐文件 SHA-256 一致。

| 检查 | Windows | Ubuntu 24.04 |
| --- | --- | --- |
| 根 CMake 与完整 CTest | 18/18 | 18/18 |
| 原生 FileGDB 集成 | 通过，83 个异常/保护检查 | 通过，84 个异常/保护检查 |
| 最小部署与复制 GDB 独立回读 | 通过 | 通过 |
| 安装后 Python 客户端 | 14 场景，9 份 GDB 复制回读 | 14 场景，9 份 GDB 复制回读 |
| Python 契约测试 | 35 项，3 项平台/权限跳过，其余通过 | 35 项，2 项 Windows MAX 测试跳过，其余通过 |

| 固定依赖散列、安装许可、版本一致性 | 通过 | 通过 |

完整 CTest 保留并发输出、链接路径、材质/UV/法线角点边界、放置来源和流式 Scene JSON 覆盖。原生测试实际写入纹理 GDB，关闭并重开核验；独立复制回读在新进程执行，未使用桌面 GIS 软件。

另在 Windows 对最终 CLI 执行分片 DAE 专项原生验证，16/16 检查通过。注释/CDATA 分布于变换、索引及纹理 URI；与普通文本模型的 Bundle 几何、节点、材质、纹理、坐标和诊断逐项一致。核对 6 个独立角点、2 个三角形、UV、法线、纹理原始字节和标量 Alpha，使用 WKID 32650、原点 `(500000, 3000000, 100)` 写入 GDB。复制数据库后隐藏源模型、纹理及两个 Bundle，复制品仍通过独立 writer 进程的 `standalone_copy_verified` 核验。

## 读取性能取舍

使用现有 `scripts/benchmark_dae_reader.py`，比较本次修改前后的同版本 Release CLI。`triangles` 和 `polylist` 各含 30 万三角形、90 万独立角点，每组交替顺序运行三次，以下为中位数。所有前后报告内容一致。

| 平台 / 输入 | 耗时：修复前 → 后 | 峰值驻留内存：前 → 后 |
| --- | --- | --- |
| Windows / triangles | 0.772 → 0.808 秒 | 118.47 → 118.46 MiB |
| Windows / polylist | 0.796 → 0.830 秒 | 119.63 → 119.62 MiB |
| Ubuntu 虚拟机 / triangles | 2.120 → 2.133 秒 | 93.55 → 93.55 MiB |
| Ubuntu 虚拟机 / polylist | 2.233 → 2.102 秒 | 94.69 → 94.69 MiB |

本次主要收益是正确性和错误可诊断性。减少新增校验的开销后，Windows 这组合成读取仍增加约 4%–5% 耗时；峰值内存没有实质增长，上一轮取消完整索引副本的优化得以保留。Ubuntu 为 CPU 仿真环境，其时间不代表原生硬件吞吐量；这些结果不代表生产模型或 FileGDB 写入性能。

本次构建、CTest、原生/部署/Python/GUI 测试、旧版反例、专项 GDB 回读、基准样本摘要及源码散列见 [证据目录](evidence/boundary-2026-10-03/)。
