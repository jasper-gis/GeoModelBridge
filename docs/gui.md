# GeoModelBridge GUI · V0.1.4

本次发布入口为 `releases/V0.1.4/bin/geomodelbridgeGUI.exe`，保留整个 `releases/V0.1.4` 目录。下文 `dist` 是源码构建的默认安装目录；现有 V0.1.3 的 `dist` 保留。

V0.1.4 限量预览大量及超长日志，并显示折叠数量；完整模型诊断仍在转换报告中。报告缺少必要的回读验证字段时，中文摘要会列出缺项，不会把成功状态文字单独当作有效核验。

入口为 `dist/bin/geomodelbridgeGUI.exe`。这是 Windows x64 中文桌面程序，以自包含方式发布，无需另装 .NET。保留整个 `dist` 目录：界面会调用旁边的 `geomodelbridge.exe`，再启动所选后端。

本版默认选择“GIS 静态兼容”，并在界面中列出会执行的兼容处理。遇到报告中的多条重复问题时，可直接查看按原因归并的中文摘要。

## 转换一个 FBX

1. 双击程序，点“检查运行环境”，确认所需程序和所选后端运行条件可用。
2. 选择输入 `.fbx`，指定一个**尚不存在**的输出 `.gdb` 路径。已有成果和报告不会被覆盖。
3. 确认转换策略。默认“GIS 静态兼容”适合按模型保存的静态姿态转换；若希望遇到活动动画、额外光照通道或退化面时停止，选择“严格检查”。具体区别见下表。
4. 选择写入后端。原生 FileGDB 后端不依赖 Pro；ArcGIS Pro 后端要求本机安装 Pro 且许可可用。切换后端后应重新检查运行环境。
5. 填写目标投影坐标系的 WKID，以及以米计的 X/Y/Z 原点。初始值留空，必须明确填写；要素类名称默认 `Models`。
6. 如果贴图在 FBX 目录以外，在附加贴图目录中逐行添加其所在目录。程序不会联网查找缺失贴图。
7. 点“开始转换”，在日志区查看进度和诊断。成功后点“打开输出目录”或“查看转换报告”。

WKID 只赋予空间参考，原点只平移归一化后的模型；它们不能代替配准、旋转对齐或重投影。目标坐标系须为以米计的投影坐标系。请使用模型实际位置对应的参数。

## 选择转换策略

| 模型内容 | GIS 静态兼容（GUI 默认） | 严格检查 |
|---|---|---|
| 空动画容器、中性的标准默认材质属性 | 接受；空容器记录提示 | 相同 |
| 真实动画曲线 | 使用 FBX 文件保存的节点姿态，记录兼容警告 | 停止转换 |
| 活动环境光、高光、反射及其专用贴图 | 省略这些效果，保留漫反射颜色、贴图和 UV，逐材质记录 | 停止转换 |
| 缺少 JFIF、但明确为 8 位三分量 Adobe YCbCr 基线 且方向为默认值的 JPEG | 补充标准 JFIF 标记，保留原压缩数据和其余字节，记录原/新散列 | 提示需要封装修复后停止 |
| 有限坐标下严格零面积的三角形 | 删除并按网格汇总数量；删除后网格为空仍失败 | 停止转换 |
| 缺少漫反射贴图、无效 UV、非有限几何、PBR、真实位移、未知复杂材质、骨骼或形变 | 停止转换 | 停止转换 |

保存的姿态不等于动画第 0 帧或源软件当前播放帧。若要保留特定帧、光照或反射外观，请先在建模软件中导出静态快照或烘焙漫反射贴图。兼容模式不会自动完成这些操作，也不会放宽数据库回读核验。完整边界见 [转换策略说明](compatibility.md)。

JPEG 修复仅处理已明确颜色空间和方向的封装兼容问题：添加 18 字节 JFIF APP0，不重新压缩图片，不修改源文件。程序还检查颜色分量、色度定位及像素长宽比；未知颜色空间、非默认 EXIF 方向或不符合这些前提的图片仍会停止。程序不会猜测颜色或自动旋转贴图，该处理会在报告中明确标记。

## 失败后重试与防覆盖

失败时也可能已经生成 `.report.json`。为了保留排查记录，程序会拒绝再次使用这个报告路径；这并不表示生成了可用 GDB。

点输出路径旁的“换个新名称”，程序会检查数据库路径和配套报告路径，选择一个尚未占用的名称，例如 `模型_1.gdb`。它只更新输出位置，保留原成果及报告，也不会自动开始转换。检查模型位置与转换策略后，再点“开始转换”。已有成果需要保留时，不必删除旧库或旧报告。

## 演示与报告

“加载演示”填入随工程提供的测试 FBX 和明确标注的测试坐标。演示值 `32650 / 500000 / 3000000 / 100` 只用于验证流程，不能作为真实业务模型的位置。

从演示切换到其他 FBX 后，界面会清空 WKID 和 X/Y/Z 并移除演示提示，请填写新模型的实际参数。

“查看转换报告”包含“中文摘要”和“原始 JSON”两个页签。摘要按原因归并重复诊断，显示条目数、部分对象示例和处理建议；零面积清理会区分警告记录数与实际删除面数。报告字段有效时，还会显示网格、三角形、材质、贴图及已回读要素数量。完整逐项信息保留在原始 JSON 中。

GUI 的成功状态要求进程正常结束、实际 GDB 存在，并且报告的版本、后端、策略、输出、要素类、坐标系与请求匹配，数据库关闭后重开核对通过。失败报告或只有退出码 0 都不能成为成功结果。发生兼容处理时，界面显示“完成（有兼容处理）”，并提示检查外观。检查环境只验证运行条件，不能预先证明任意 FBX 都能完整转换。

不支持的材质、缺失贴图或无效参数会明确失败。日志和报告提供原因，程序不会用白模替代不支持的材质。原生后端自回读、ArcGIS Pro 独立读取和目标软件图形显示分别验收；其中一项通过不能替代另外两项。本次用户模型经过明确记录的 JPEG 封装修复，两个后端各自写入与回读通过，原生成果也通过独立 Pro 按中间包读取核验。两后端坐标量化精度不同，不代表文件逐位相同。颜色、Alpha 和目标软件显示结论仍按 [验收说明](acceptance.md) 区分，V0.1.1 的完整图形验收待办继续保留。

历史界面与操作证据见 [V0.1.2 验证记录](validation-v0.1.2.md)，未改写为本版证据。

## 构建与交付

在工程根目录运行：

```powershell
.\scripts\build.ps1 -WithGui
```

这会构建、测试并安装 C++ CLI，再发布 GUI 到 `dist/bin`，并将实际还原的 .NET/WPF 运行时原始许可及来源散列复制到 `dist/licenses/dotnet`。需要 CMake、C++17 工具链、Python 3 和 .NET 8 或更高 SDK；首次发布可能需要下载 Windows x64 .NET 运行时包。现有后端不会因此重新生成，可用 `-WithNative` 或 `-WithPro` 一并构建，参数见 [README](../README.md)。

本版交付工程目录及其中的程序，不创建 ZIP。没有三维预览、批量队列、自动配准或烘焙功能；界面中的转换使用与命令行相同的支持范围。
