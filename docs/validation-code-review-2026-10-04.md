# 层级验证优化与输入边界修复 — 2026-10-04

本轮基于 `master` 的 `cd71ceb`，版本保持 `0.6.0`，改动列入 Unreleased。修复三个可复现问题，沿用 Scene Bundle、原生 FileGDB 编码及现有材质、法线、UV、定位和独占写出契约。

## 改动与回归

- **共享层级验证**：此前每个节点重新遍历全部祖先，深链和通向循环的链需要 O(N²) 次遍历。现在每次验证使用一个字节/节点的状态表，迭代完成每条路径，总体 O(N)，无递归。循环节点及所有通向循环的节点仍各自报告 `NODE_CYCLE`；非法父节点、自引用和诊断顺序保持一致。新增混合拓扑、修复后重新验证、100,000 节点有效链及通向循环的链测试；原生入口新增三项非法层级拒绝检查，确认不产生 GDB 或成功报告。
- **WRL/X3D 旋转**：有限轴 `(1.7e308, 1.7e308, 1.7e308)` 的直接长度溢出，曾把旋转误算成缩放。已复现 2×3 米四边形的边长变成约 1.6507×2.4760 米。改为先按最大绝对分量缩放，再归一化，也避免次正规数长度舍入造成变形。两种格式分别覆盖 `rotation` 和正/逆 `scaleOrientation`，比较普通轴、极大轴、最小次正规轴的源矩阵、位置、法线、UV、三角形、材质与纹理；零轴仍明确拒绝。新回归在旧二进制上失败，在修复后通过。
- **Python 坐标参数**：非 OBJ 输入传入非默认 `obj_up_axis` 或 `obj_unit_meters`，此前会被静默忽略。转换与检查现在共用启动前验证并返回 `INVALID_REQUEST`。新增 8 种格式 × 2 种参数 × 2 种操作的 32 个回归场景，核对进程没有启动、输入字节未改变、没有输出。OBJ 自身的合法设置继续由现有集成测试覆盖。

## 层级验证基准

Windows x64，MSVC 19.44.35226.0，使用与根工程 Release 一致的 `/O2 /Ob2 /DNDEBUG`，另设 `/std:c++17 /EHsc /MD`。相同测试程序分别链接改动前、后的 `core.cpp`，交替运行 5 次，下表为中位数。每次只计 `gmb::validate()`，不计场景构造；场景含一个有效三角形和指定节点拓扑。

| 节点数 | 拓扑 | 改动前 | 改动后 |
| ---: | --- | ---: | ---: |
| 10,000 | 有效链 | 87.3344 ms | 0.3436 ms |
| 10,000 | 链进入循环 | 175.535 ms | 1.3029 ms |
| 30,000 | 有效链 | 1022.91 ms | 1.0791 ms |
| 30,000 | 链进入循环 | 1960.56 ms | 5.3417 ms |

40 个样本的诊断数量都符合预期：有效链为 0，循环场景为节点总数。基准源码、编译参数、源码散列、逐次样本和编译器版本保存在[证据目录](evidence/code-review-2026-10-04/)。可从基线 `cd71ceb:src/core.cpp` 和本次 `src/core.cpp` 取两份源码，以记录的参数分别编译 `hierarchy-benchmark.cpp` 后复测。此结果是合成层级验证的局部测量，运行期间宿主还有虚拟机测试负载，不代表所有生产模型或完整 GDB 转换的吞吐提升。
