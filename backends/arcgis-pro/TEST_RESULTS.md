# V0.1.0 ArcGIS Pro writer 验证记录

验证日期：2026-09-20。实际环境：Windows x64，ArcGIS Pro 3.6.2.59530，.NET SDK 10.0.203，.NET 8.0.26。Release 构建为 0 warning / 0 error。运行测试脚本：`tests/integration.py`。

## 已通过

1. 在真实 FileGDB 中创建 2 个 Multipatch 要素：共 3 个材质 patch，覆盖 PNG、JPEG、纯色和整体透明度。
2. 关闭数据库后重新打开，核对要素/patch/角点数、坐标、材质、UV、法线、属性、图片尺寸/编码以及纹理完整字节。
3. 2×2 RGBA PNG 的 alpha=0、1、127、255 均保持，包括 alpha=0 像素的隐藏 RGB。原始测试像素与 GDB 回读摘要相同：`74e204bdbae49352f72ee1c07cf3fae8615fddf74e0c37a12416d1fdd8802e92`。
4. JPEG 原始压缩字节与 GDB 回读字节 SHA256 相同，未重编码。
5. RGB `[0.13,0.58,0.91]` 量化为 `[33,148,232]`；alpha `0.427` 量化为 57% 整体透明度。报告同时保留源值与目标值。
6. `source` 和完整 snake_case `reader_diagnostics` warning 持久保留在报告。
7. 把已关闭的 GDB 复制到新目录，将原 bundle 目录搬离原路径，在新进程中只给复制 GDB 与原报告进行独立验收，得到 `standalone_copy_verified`。纹理和几何不需要源文件。
8. 既有 GDB/报告不覆盖；报告位于源 bundle 或 GDB 内时拒绝写入。

## 19 项失败路径均通过

错误 SHA256、路径 `..` 越界、绝对图片路径、MIME 与签名不匹配、未支持图片格式、缺失 UV、零法线、非单位法线、非有限坐标、超范围颜色、非法材质索引、非法顶点索引、地理坐标系、英尺坐标系、缺少显式 origin、未知 WKID、reader error、真实 GDB 写入失败临时目录清理，以及复制验证纹理 hash 不匹配。

写入失败测试使用有限但超出 GDB 可表达范围的坐标。测试进程确实观察到本次随机 staging GDB 创建，然后确认操作失败、staging 被清理、最终 GDB 和成功报告未产生。独立验证故意篡改预期纹理 hash 后明确失败，不产生成功报告。

最终回归机器证据目录名：`arcgis-pro-integration-xqso66t6`，保留于工作区 `work/writer-research/`。测试脚本每次新建随机目录，结果可复现；交付时无需携带这些开发中间文件。

## 非轴向法线发现与修复

真实 `sloped_normals.fbx` 回归暴露了一个首轮轴向法线样例未覆盖的问题。源法线 `(0,-0.8,0.6)` 经 `MultipatchBuilderEx.ToGeometry` 为 `(0,-0.800000011920929,0.6000000238418579)`，仅有 float32 误差；写入 FileGDB 并关库重开后变为 `(0,-0.796875,0.6015625)`，与普通浮点误差明显不同。

独立 CoreHost probe 在同一真实 FileGDB 中测试 12,265 个单位法线：6 个坐标轴方向、斜面和均分三轴、2,001 个单位圆截面点、固定种子 10,000 个随机单位方向，以及 256 个正负精确半步临界值。36,795 个分量全部精确满足：

```text
builder_component = float32(source_component)
stored_component  = floor(builder_component * 128 + 0.5) / 128
```

正半步 `+1/256 → +1/128`，负半步 `-1/256 → 0`，说明精确半步朝正无穷舍入。坐标轴 ±1 保持不变。存储后的向量未重新归一化。此结论是 Pro 3.6.2.59530 的数据路径实测，未找到 Esri 对该量化规则的公开跨版本保证，因此不将它描述为官方格式精度契约。

| 量 | 12,265 个 probe 样本中的最大观测值 |
|---|---:|
| builder 分量误差 | 2.9801916268112905e-8 |
| GDB 分量误差 | 0.00390625（1/256） |
| 方向角误差 | 0.36912596670901104° |
| 向量长度误差 | 0.005993998879342266 |

这些是样本中的观测值，不是任意模型的最大误差承诺。`sloped_normals.fbx` 本身实测最大分量误差约 0.003125、方向角误差约 0.17932893°、长度误差约 0.00155761。

修复未放宽原来的通用浮点容差：builder 法线须匹配源值的 float32 表示，数据库回读必须逐分量**精确匹配上述量化预测**；其他结果仍失败。报告 `checks[].normal_storage` 单独保存源角点法线 SHA256、量化角点数量、步长/半步/舍入规则、最大 builder 分量误差、GDB 分量/角度/长度误差。`signature` 继续对真实回读法线做精确 hash，复制后验证不使用有损容差。

最终集成测试额外覆盖斜面 `(0,-0.8,0.6)`、均分三轴、正负半步边界。真实斜面 FBX 已成功写入并回读；19 项失败路径、PNG/JPEG 保真、warning 保留和隐藏源文件后的独立复制验证均再次通过。probe 的代码、完整结果与摘要保留在开发工作区 `work/sloped-probe/`。
